# Gibson ODE Periodic-Orbit Reproduction Status

Last updated: 2026-05-02

## Goal

The goal is to reproduce the four Gibson periodic orbits from `notebooks/periodic_orbits/gibson` inside the low-dimensional CloudAtlas ODE model. In practical terms, we want ODE periodic orbits whose trajectories match the DNS orbit geometry in physically meaningful diagnostics such as power input `I` and dissipation `D`, and then eventually project those ODE solutions back into DNS/Channelflow for validation.

The ideal workflow is ODE-first:

1. Start from a DNS solution only as an initial hint, by projecting `ubest.nc` into the ODE basis.
2. Use the ODE dynamics to find or refine a periodic orbit.
3. Verify that the ODE orbit is nontrivial and has Gibson-scale `I-D` excursions.
4. Only after that, lift/project the ODE result back toward DNS.

The current primary test case is orbit 1 at:

- `Re = 200`
- `alpha = 1`
- `gamma = 2`
- symmetry group generated by `sxyz` and `sztxz`
- ODE resolution `J,K,L = 2,4,7`
- ODE dimension `m = 169`

## Important Lesson So Far

A small closing residual by itself is not enough. Several solvers reduce `||phi_T(x)-x||` by collapsing onto a tiny loop or near-equilibrium in the ODE model. We must always track `I_span` and `D_span`.

For the projected DNS start at `J2_K4_L7`, the one-period ODE trajectory has large, DNS-like scale:

- initial closing residual: `9.0937e-02`
- `I_span`: `3.1233e-01`
- `D_span`: `3.2845e-01`

Any candidate with `I_span,D_span ~ 1e-5` is a collapsed/tiny orbit, not the Gibson orbit.

## Scripts Added

### `reproduce_gibson_orbits_ode.jl`

Initial reproduction attempt. It projects the DNS `ubest.nc` into the ODE basis and tries direct periodic-orbit machinery.

Outcome:

- At `J2_K4_L7`, the projected start had reasonable projection error:
  - `L2Dist(u,uout)/L2Norm(u) ~= 8.99e-3`
  - projected closing residual over the DNS period: `~9.09e-2`
- BifurcationKit collocation from the one-period projected DNS seed diverged:
  - residual grew from `~9.1e-2` to `~1.39e4` in 5 Newton steps.

### `ode_recurrence_search.jl`

ODE-first recurrence search:

1. Project DNS `ubest.nc` to ODE coefficients.
2. Integrate the ODE forward.
3. Search the ODE trajectory for near recurrences.
4. Refine recurrence candidates with BifurcationKit collocation.

Useful result:

- The ODE trajectory does produce near recurrences.
- Some early recurrence seeds preserve moderate `I-D` motion:
  - rank 1 seed: `T = 53`, relative distance `7.52e-3`, `I_span = 7.62e-2`, `D_span = 5.98e-2`
  - ranks 1-5 are all around `T = 52-53`.

Failure mode:

- Collocation refinement improved closure but collapsed the span.
- Example rank 1:
  - seed `I_span = 7.62e-2`, `D_span = 5.98e-2`
  - refined closing residual `1.91e-5`
  - refined `I_span = 1.46e-3`, `D_span = 1.02e-3`
- This is another tiny-loop failure.

### `anchored_shooting_refine_ode_orbits.jl`

Shape-anchored shooting based on ODE recurrence candidates. This uses the existing low-level `hookstepsolve` on an overdetermined residual:

- closure residual
- phase condition
- soft anchors on sampled `I(t),D(t)`
- period anchor

Outcome for orbit 1, rank 1:

- It preserved the recurrence seed scale:
  - `I_span ~= 7.61e-2`
  - `D_span ~= 6.00e-2`
- Closing residual improved to about `1.10e-3`.

Interpretation:

- This is better than the collapsed collocation result.
- But the loop is still significantly smaller than the full Gibson DNS-scale orbit.

### `direct_hookstep_po_from_dns_projection.jl`

Classic phase-fixed direct shooting from the projected DNS state using:

```julia
hookstepsolve_rpo(model, Re, Symmetry(), x0_projected, T_dns, params)
```

This solves the exact periodic-orbit equations:

```text
phi_T(x0) - x0 = 0
dot(f(x0), x0 - xref) = 0
```

Outcome at `J2_K4_L7`:

- initial projected seed:
  - closing `9.0937e-2`
  - `I_span = 3.1233e-1`
  - `D_span = 3.2845e-1`
- after hookstep:
  - closing `1.3548e-5`
  - `I_span = 1.3136e-5`
  - `D_span = 1.3231e-5`
  - elapsed `~1032 s`

Interpretation:

- This successfully found a nearly closed solution.
- But it collapsed to a tiny near-equilibrium loop.
- It is not the Gibson orbit.

### `guarded_direct_hookstep_po_from_dns_projection.jl`

Guarded direct shooting from the projected DNS state. This is currently the most promising approach.

It starts from:

- projected DNS `ubest.nc`
- DNS period from `Tbest.asc`

It solves an overdetermined residual with:

- direct closure `phi_T(x)-x`
- phase condition
- soft anchors on the projected ODE trajectory's `I(t),D(t)` waveform
- optional period anchoring

The point is to prevent the solver from reducing closure by collapsing the orbit.

## Performance Situation

The solver is slow primarily because the hookstep Jacobian is finite-differenced.

For `J2_K4_L7`:

- unknowns: `169` coefficients plus `T`, so `170`
- each Newton step needs roughly:
  - 1 base residual evaluation
  - 170 perturbed residual evaluations
- each residual evaluation is a full ODE integration over `T ~= 59`

So a single Newton step costs roughly 171 full-period ODE integrations, plus additional hookstep trial evaluations.

Low-hanging optimization already applied:

- `Df_finitediff` in `src/Hookstep.jl` now parallelizes finite-difference Jacobian columns when `JULIA_NUM_THREADS > 1`.
- Serial and threaded finite-difference Jacobians matched exactly on a small consistency test.

Recommended command pattern for future expensive guarded runs:

```bash
JULIA_NUM_THREADS=8 \
CLOUDATLAS_SKIP_ACTIVATE=true \
GIBSON_ORBIT_IDS=1 \
GIBSON_JKL=2x4x7 \
GIBSON_DIRECT_START_FROM_WEIGHT=1 \
GIBSON_DIRECT_ANCHOR_WEIGHTS=0.3,0.1,0.03 \
GIBSON_DIRECT_ANCHOR_SAMPLES=8 \
GIBSON_SOLVER_ABSTOL=1e-8 \
GIBSON_SOLVER_RELTOL=1e-8 \
GIBSON_HOOK_NEWTON=2 \
GIBSON_HOOK_DELTA=0.002 \
julia --startup-file=no --project=. notebooks/periodic_orbits/gibson/guarded_direct_hookstep_po_from_dns_projection.jl
```

## What We Think Is Happening

The ODE model definitely contains trajectories with Gibson-like `I-D` scale near the projected DNS initial state. However, unconstrained periodic-orbit refinement tends to find much smaller nearby periodic or near-equilibrium solutions.

The guarded direct solve shows that closure can be reduced while staying on the large loop, but the current finite-difference single-shooting approach is slow and has not yet pushed closure below `~5e-2`.

## Suggested Next Steps

1. Continue the guarded-direct ladder from `w1p0` to smaller weights such as `0.3,0.1,0.03`, using threaded finite differences.

2. Track both closure and span. A good next result would reduce closure below `5e-2` while keeping:
   - `I_span ~ 0.3`
   - `D_span ~ 0.3`

3. If the orbit collapses when anchor weight decreases, stop that path and treat the current candidate as evidence that the ODE shadows the DNS orbit but the exact PO may not exist at this truncation/parameterization.

4. Implement a real shooting Jacobian via variational equations. This is the main performance improvement. It would replace about 171 full ODE integrations per Newton step with one augmented integration of the state plus tangent map.

5. Consider multiple shooting or collocation with a better-scaled/guarded formulation. This may be more robust than single shooting once a large-loop candidate is available.

6. Eventually repeat the successful path for Gibson orbits 2-4, but orbit 1 should remain the development case until the method can preserve span and reduce closure reliably.

## Open Questions

- Can the large-loop candidate be improved by increasing resolution, or does that mainly increase cost?
- Would a variational-equation Jacobian make the current guarded shooting approach good enough, or do we need a multiple-shooting formulation?
